
# Teach Me — из конспекта в учебные карточки

Teach Me — учебное Django-приложение, которое превращает текстовый конспект в вопросы, ответы и цитаты из исходного текста. Конспект и карточки сохраняются в SQLite и доступны по постоянной ссылке.

Приложение предназначено для локального использования и демонстрации на localhost. Полноценной авторизации и аккаунтов пользователей нет.

## Возможности

- Ввод названия и текста конспекта.
- Генерация учебных карточек в режимах DEMO и LIVE.
- Сохранение конспекта и карточек в SQLite.
- Просмотр сохранённого конспекта.
- Раскрытие ответов и цитат.
- Редактирование вопросов, ответов и цитат.
- Проверка цитаты на наличие в исходном конспекте.
- Удаление отдельной карточки с подтверждением.
- Ручная отметка карточки как проверенной.
- Возврат проверенной карточки на повторную проверку.
- Фильтрация карточек по статусу.
- Отображение общего количества карточек и количества проверенных карточек.

В режиме DEMO используется заранее подготовленный пример конспекта о компьютерных сетях и три карточки. Этот режим позволяет демонстрировать приложение без API-ключа и обращения к внешнему сервису.

## Требования

- Python 3.10 или новее.
- Django `>=5.2,<5.3`.
- python-dotenv `>=1.1,<2`.

## Установка на Windows

Открой PowerShell и перейди в каталог проекта, где находится `manage.py`.

Создай виртуальное окружение:

```powershell
python -m venv .venv
```

Установи зависимости:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

## Установка на macOS и Linux

Перейди в каталог проекта, где находится `manage.py`.

Создай виртуальное окружение:

```bash
python3 -m venv .venv
```

Активируй его:

```bash
source .venv/bin/activate
```

Установи зависимости:

```bash
python -m pip install -r requirements.txt
```

## Настройка окружения

В каталоге с `manage.py` создай файл `.env`, используя `.env.example` как шаблон.

Пример содержимого:

```dotenv
TEACHME_MODE=demo
GEMINI_API_KEY=
GEMINI_MODEL=
GEMINI_TIMEOUT_SECONDS=25
```

### Режим DEMO

```dotenv
TEACHME_MODE=demo
```

DEMO не требует API-ключа. Для демонстрации используй подготовленный пример конспекта о компьютерных сетях. Другой текст может быть отклонён DEMO-провайдером.

### Режим LIVE

Для использования Gemini API укажи параметры:

```dotenv
TEACHME_MODE=live
GEMINI_API_KEY=your_api_key
GEMINI_MODEL=your_model_name
GEMINI_TIMEOUT_SECONDS=25
```

Замени `your_api_key` и `your_model_name` действительными значениями, поддерживаемыми используемой конфигурацией Gemini.

API-ключ должен храниться только в локальном `.env`. Не публикуй его в GitHub, исходном коде или скриншотах. Файл `.env` не следует добавлять в Git.

Работа LIVE зависит от правильности ключа, имени модели, сетевого соединения и доступности API. Успешный запуск DEMO не подтверждает работоспособность LIVE.

## Работа с конспектом

### Создание конспекта

1. Открой главную страницу.
2. Введи название и текст материала.
3. Отправь форму.
4. После генерации приложение сохранит конспект и карточки.
5. Откроется страница созданного набора.

У сохранённого конспекта есть постоянный URL:

```text
http://127.0.0.1:8000/sources/<pk>/
```

Вместо `<pk>` используется идентификатор конспекта.

Чтобы снова открыть набор, используй его URL или выбери конспект на главной странице.

### Просмотр карточек

На странице конспекта отображаются вопросы и статусы карточек.

Для просмотра ответа и цитаты нажми «Показать ответ». Ответ и цитата раскрываются внутри карточки.

Исходный текст конспекта можно открыть отдельно через блок «Показать исходный конспект».

### Редактирование карточки

Нажми «Редактировать» под нужной карточкой.

Можно изменить:

- вопрос;
- ответ;
- цитату из исходного конспекта.

После сохранения приложение проверяет поля формы. Цитата должна присутствовать в исходном тексте конспекта.

Если карточка была проверена, после успешного редактирования её статус автоматически сбрасывается на «Нужно проверить».

### Удаление карточки

Нажми «Удалить» под нужной карточкой.

Откроется страница подтверждения удаления. Для удаления нажми кнопку подтверждения. Чтобы отменить действие, вернись к конспекту.

Удаляется только выбранная карточка. Сам конспект и остальные карточки сохраняются.

### Проверка карточки

Сравни вопрос, ответ и цитату с исходным конспектом.

Если карточка проверена вручную, нажми «Я проверил карточку».

Статус изменится на «Проверено». Чтобы вернуть карточку на повторную проверку, нажми «Вернуть на проверку».

Статус сохраняется в базе данных в поле `is_verified`.

### Фильтры карточек

На странице конспекта доступны три фильтра:

- «Все» — показывает все карточки текущего конспекта.
- «Нужно проверить» — показывает карточки со статусом `is_verified=False`.
- «Проверенные» — показывает карточки со статусом `is_verified=True`.

Числа возле фильтров всегда относятся ко всему набору, а не только к текущему списку.

Если в выбранном фильтре нет карточек, отображается сообщение и ссылка «Показать все».

Если в конспекте вообще нет карточек, исходный текст конспекта остаётся доступен.

Фильтрация выполняется через запрос к базе данных. Карточки других конспектов в список не попадают.

## Проверка проекта

Все команды выполняются из каталога с `manage.py`.

Проверка конфигурации Django:

```bash
python manage.py check
```

Запуск тестов приложения:

```bash
python manage.py test study
```

Проверка отсутствия новых изменений моделей, требующих миграций:

```bash
python manage.py makemigrations --check --dry-run
```

На Windows:

```powershell
.\.venv\Scripts\python.exe manage.py check
.\.venv\Scripts\python.exe manage.py test study
.\.venv\Scripts\python.exe manage.py makemigrations --check --dry-run
```

Команда `python manage.py test study` запускает тесты из `study/tests.py` и `study/test_editor.py`.

Результаты необходимо записывать по фактическому выводу терминала. Ожидаемый результат не является подтверждением успешного выполнения.

## Структура приложения

Основные файлы приложения `study`:

- `study/models.py` — модели конспекта и карточек.
- `study/forms.py` — формы создания конспекта и редактирования карточек.
- `study/services.py` — генерация карточек и проверка результата.
- `study/views.py` — обработка запросов, сохранение и просмотр данных.
- `study/urls.py` — маршруты приложения.
- `study/templates/study/home.html` — главная страница.
- `study/templates/study/source_detail.html` — страница конспекта и карточек.
- `study/templates/study/card_form.html` — форма редактирования карточки.
- `study/templates/study/card_confirm_delete.html` — подтверждение удаления.
- `study/tests.py` — тесты генерации и сохранения из лабораторной №8.
- `study/test_editor.py` — тесты редактирования, удаления, проверки и фильтрации карточек.

## Ограничения

- DEMO использует заранее подготовленный демонстрационный материал.
- Проверка цитаты подтверждает, что цитата присутствует в исходном тексте. Она не доказывает истинность ответа или достоверность самого конспекта.
- Проверка карточки выполняется пользователем вручную. Автоматической проверки правильности ответа нет.
- Качество карточек, созданных в LIVE, зависит от модели и исходного материала.
- В приложении нет полноценной авторизации и разграничения данных по владельцам.
- Приложение предназначено для локального учебного использования, а не для промышленного развёртывания.
